CBMS Administrator Control Manual

ระบบจัดการผู้ช่วย AI และบอทตอบคำถาม CBMS Admin Portal

ยินดีต้อนรับผู้ควบคุมระบบ คณะกรรมการจัดทำ และเจ้าหน้าที่แอดมินทุกท่าน เอกสารคู่มือนี้สรุปส่วนการจัดการระบบหลักสำหรับ **ผู้ดูแลระบบ (Administrator)** ของโครงการ **CBMS** ซึ่งเป็นโครงสร้างแบบ Multi-Bot (ระบบบอทหลายตัวแยกตามจุดประสงค์ของแผนก) ทำงานร่วมกับ RAG อัตโนมัติ โดยแบ่งกลุ่มฟีเจอร์การจัดการออกเป็น **การจัดการข้อมูลและการตอบกลับของบอท** และ **การตั้งค่าโครงสร้างพื้นฐานระบบ**

🛡️ ระบบการแบ่งสิทธิ์ผู้ใช้งาน (Role-Based Access Control)

ระบบความปลอดภัยของหลังบ้านจะผูกสิทธิ์เข้ากับระบบ **Microsoft Azure AD (Office 365 @up.ac.th)** และตรวจสอบสิทธิ์แบบไดนามิกผ่าน **CAMS API** ของมหาวิทยาลัยพะเยา โดยแบ่งออกเป็น 3 ระดับสิทธิ์:

1. Super Admin ผู้ควบคุมสูงสุด มีสิทธิ์สร้าง/ลบบอท, จัดการโมเดล AI ของระบบทั้งหมด, ตั้งค่าความปลอดภัย, จัดการเพิ่ม/ลบผู้ใช้แอดมินคนอื่นๆ ได้ครบถ้วน
2. Admin มีสิทธิ์บริหารจัดการฐานความรู้ (Knowledge), ตอบกลับคำขอด่วน (Handoff), ดูผลวิเคราะห์ Analytics และปรับแต่งโปรไฟล์คำต้อนรับของบอทที่ตนเองดูแล
3. Viewer (ผู้สังเกตการณ์) สิทธิ์ในการเข้าชมรายงาน รายการข้อความ และสถิติข้อมูล Token Usage ได้อย่างเดียว ไม่สามารถแก้ไข เพิ่มเติม หรือลบข้อมูลใดๆ ในระบบได้
1

เมนูที่ 1: Dashboard (รายงานสถิติหลักแบบ Live)

หน้าจอแรกที่จะปรากฏหลังเข้าสู่ระบบ ทำหน้าที่สรุปข้อมูลเชิงสถิติที่สำคัญของบอทตัวที่ใช้งานปัจจุบัน ประกอบด้วยกล่องแสดงสถิติแบบ Real-time และกราฟสรุปจำนวนผู้ใช้งานต่อวัน ช่วยให้เห็นแนวโน้มความสนใจและประสิทธิภาพของบอทได้ทันที

🔴 จุดเน้นวงกลมสีแดง: แถบทางซ้ายจะไฮไลต์เมนู Dashboard ในแถบ Sidebar ซึ่งเป็นเมนูระดับบนสุด แสดงผลวิเคราะห์ภาพรวม เช่น จำนวนบทสนทนา (Conversations), จำนวนคำถามทั้งหมด (Messages), และความเร็วเฉลี่ยในการตอบของ AI
2

เมนูที่ 2: Conversations (รายการบทสนทนาทั้งหมด)

เมนูสำหรับการตรวจสอบการสนทนาจริงระหว่างผู้ใช้กับแชทบอท แอดมินสามารถเข้ามาดูรายละเอียดประวัติการพูดคุยของแต่ละ Session, แพลตฟอร์มที่เชื่อมต่อ (เช่น Web, LINE, Facebook) และสามารถคลิกที่ปุ่มแว่นขยายเพื่ออ่านบันทึกแชทฉบับเต็มเพื่อตรวจความถูกต้องของเนื้อหาได้

🔴 จุดเน้นวงกลมสีแดง: แถบซ้ายมือจะเน้นตำแหน่งเมนู Conversations แสดงตารางข้อมูลผู้ติดต่อล่าสุด ตัวกรองการค้นหาตามคีย์เวิร์ด และปุ่มดูบันทึกแชท
3

เมนูที่ 3: Analytics (รายงานวิเคราะห์สถิติเชิงลึก)

หน้าวิเคราะห์ประสิทธิภาพในระยะยาว แสดงผลสถิติเปอร์เซ็นต์คำตอบที่ถูกต้อง สถิติการตอบกลับแบบผิดพลาด (Fallback Rate) อัตราความพึงพอใจของคะแนนการประเมินจากผู้ใช้งาน และแสดงสัดส่วนการเรียกใช้งานแชทแยกตามแต่ละแพลตฟอร์มปลายทาง

🔴 จุดเน้นวงกลมสีแดง: ไฮไลต์เมนู Analytics บนระบบ แสดงหน้าจอและกราฟแท่งเปรียบเทียบประสิทธิภาพ ความถี่การใช้งานรายชั่วโมง/รายวันของบอท
4

เมนูที่ 4: Token Usage (ปริมาณการใช้งาน Token และค่าใช้จ่าย)

การบริหารโมเดล AI ผ่าน OpenRouter จะมีค่าใช้จ่ายผันแปรตามจำนวน Token ที่ประมวลผล (คำถามส่งไป + คำตอบที่สร้างขึ้น) เมนูนี้มีตารางรายงานแยกอย่างละเอียดตามรายโมเดลของ OpenRouter (เช่น GPT, Claude) เพื่อให้ผู้บริหารตรวจสอบยอดโควตาและงบประมาณสะสมได้แม่นยำ

🔴 จุดเน้นวงกลมสีแดง: ไฮไลต์เมนู Token Usage ในแถบคำสั่งซ้ายมือ สำหรับตรวจสอบโควตาการประมวลผลคำสั่งภาษาและค่าใช้จ่ายสะสมเป็นสกุลเงินดอลลาร์
5

เมนูที่ 5: Reports (หน้ารายงานผลและการส่งออกข้อมูล)

เมนูสำหรับออกเอกสารรายงานสถิติและข้อมูลการบันทึกแชท แอดมินสามารถใช้ตัวกรองตามช่วงเวลา (Start/End Date) และกดปุ่ม Export เพื่อดาวน์โหลดไฟล์สรุปในรูปแบบตาราง Excel หรือ CSV ไปใช้ในการประชุมผู้บริหารต่อไป

🔴 จุดเน้นวงกลมสีแดง: แถบ Sidebar ไฮไลต์ที่ Reports แสดงหน้าการดาวน์โหลดข้อมูลดิบและสถิติรายสัปดาห์/รายเดือน
6

เมนูที่ 6: Knowledge Base (การจัดการฐานข้อมูลความรู้บอท)

นี่คือ **"สมอง"** หลักของแชทบอท! แอดมินสามารถอัปโหลดเอกสาร PDF, Word หรือป้อนบทความ Q&A ลงในระบบ จากนั้นระบบ RAG จะแบ่งเนื้อหาออกเป็น Chunk ย่อยๆ และทำ Vector Embedding ให้บอทใช้ในการตอบคำถาม มีระบบซิงค์ไฟล์กับ Google Drive อัตโนมัติด้วย

🔴 จุดเน้นวงกลมสีแดง: เน้นที่เมนู Knowledge Base ในแถบด้านข้าง แสดงปุ่ม Sync จาก Google Drive บัญชีเอกสารส่วนกลาง และตารางรายการข้อมูลความรู้ที่ผ่านการจัดเก็บเวกเตอร์ในระบบ
7

เมนูที่ 7: Wiki Knowledge (ชั้นความรู้ที่ AI เรียบเรียงเป็นหน้า)

Wiki Knowledge คือ ชั้นความรู้ยกระดับ ที่ต่อยอดจาก Knowledge Base เดิม แทนที่จะให้บอทค้นจาก "เศษเนื้อหา (Chunk)" ที่ถูกตัดออกจากเอกสารดิบทุก ๆ ~1,200 ตัวอักษร ระบบจะให้ AI อ่านเอกสารทั้งฉบับแล้วเรียบเรียงใหม่เป็น "หน้า Wiki" แยกตามหัวข้อที่ผู้ใช้มักถาม (เช่น "เวลาเปิดทำการ", "การยืม-คืนหนังสือ") โดยแต่ละหน้าจบครบในตัว พร้อมชุด "คำถามตัวอย่าง" ที่คนจริงน่าจะพิมพ์ถามหน้านั้น

⚠️ ปัญหาของระบบเดิม (Knowledge Base อย่างเดียว):
  • เอกสารถูกตัดเป็น Chunk กลางเนื้อหา ทำให้ข้อมูลเรื่องเดียวกันกระจายคนละท่อน บอทตอบไม่ครบ
  • Embedding ภาษาไทยได้คะแนนต่ำ คำถามสั้น ๆ อย่าง "เปิดกี่โมง" มักค้นไม่เจอ กลายเป็น Fallback
  • บอทไม่รู้ว่าตัวเองมีความรู้เรื่องอะไรบ้าง ตอบได้แค่ "ไม่มีข้อมูล" แนะนำหัวข้อใกล้เคียงไม่ได้

🔄 ขั้นตอนการทำงาน (Workflow)

1. สร้างร่าง (Build)

AI อ่านเอกสารใน Knowledge Base แล้วร่างเป็นหน้า Wiki หลายหน้า พร้อมคำถามตัวอย่าง — ทุกหน้าเริ่มต้นเป็นสถานะ ร่าง (Draft)

2. ตรวจทาน (Review)

แอดมิน ต้องอ่านและแก้ไข เนื้อหาที่ AI ร่าง เทียบกับเอกสารต้นฉบับก่อน เพื่อกันข้อมูลคลาดเคลื่อน (Hallucination) — นี่คือด่านสำคัญที่สุด

3. เผยแพร่ (Publish)

เมื่อกดเผยแพร่ หน้านั้นจะถูกแปลงเป็นข้อมูลใน Knowledge Base โดยอัตโนมัติ และบอทจะนำไปใช้ตอบได้ทันที

⚖️ Knowledge Base เทียบกับ Wiki Knowledge

หัวข้อ Knowledge Base (เมนูที่ 6) Wiki Knowledge (เมนูที่ 7)
หน่วยของความรู้ Chunk — เศษเนื้อหาตัดทุก ~1,200 ตัวอักษร หน้า Wiki — 1 หัวข้อจบครบในหน้าเดียว
ที่มาของเนื้อหา เอกสารดิบจาก Google Drive (ตามต้นฉบับ) AI เรียบเรียงใหม่ + คนตรวจทานก่อนใช้
วิธีที่บอทค้นเจอ เทียบคำถามกับ "เนื้อหา" (คะแนนภาษาไทยต่ำ) เทียบคำถามกับ "คำถามตัวอย่าง" (แม่นกว่ามาก)
ความครบถ้วนของคำตอบ อาจตอบไม่ครบเพราะข้อมูลกระจายหลาย Chunk ครบ เพราะรวมเรื่องเดียวกันไว้หน้าเดียว
การควบคุมคุณภาพ ใช้เนื้อหาตามต้นฉบับทันทีที่ Sync ต้องผ่านการ Approve จากคนก่อนเสมอ
ต้นทุน Token สูงกว่า (ส่ง Chunk หลายก้อนเข้า AI) ประหยัดกว่า ~60% (ส่งหน้าเดียวสั้น ๆ)
✅ ข้อดี
  • ตอบแม่นและครบขึ้น โดยเฉพาะคำถามภาษาไทยสั้น ๆ
  • ประหยัดค่า Token/ค่า AI ต่อการตอบหนึ่งครั้ง
  • คนตรวจทานก่อนเผยแพร่ ลดโอกาสบอทมั่ว
  • บอทรู้ขอบเขตความรู้ตัวเอง แนะนำหัวข้อใกล้เคียงได้
  • เมนู "วิเคราะห์หัวข้อที่ขาด" ช่วยหาเรื่องที่ผู้ใช้ถามบ่อยแต่ยังไม่มีข้อมูล
⚠️ ข้อควรระวัง / ข้อเสีย
  • มีค่าเรียกใช้ AI ตอนสั่งสร้างร่าง (Build)
  • ต้องใช้แรงคนตรวจทานก่อนเผยแพร่ทุกหน้า
  • AI อาจสรุปตกหล่นรายละเอียด ต้องเทียบต้นฉบับ
  • ถ้าเอกสารต้นทางแก้ไข ต้องสั่งสร้างร่างใหม่และตรวจทานซ้ำ
🔗 สองเมนูนี้ทำงานร่วมกันอย่างไร: Knowledge Base ยังคงเป็น "คลังเอกสารดิบ" ที่เป็นต้นทางและแหล่งอ้างอิงเสมอ ส่วน Wiki Knowledge คือ "ฉบับเรียบเรียงที่คนรับรองแล้ว" เวลาผู้ใช้ถาม ระบบจะ ค้นจากคำถามตัวอย่างของ Wiki ก่อน (ชั้นที่ 1) ถ้าตรงก็ตอบด้วยหน้า Wiki ทันที แต่ถ้าไม่ตรง จะ ตกไปค้นจาก Chunk ดิบใน Knowledge Base ตามเดิม (ชั้นที่ 2) ดังนั้นเอกสารที่ยังไม่ได้ทำเป็น Wiki ก็ยังตอบได้ ไม่มีอะไรหายไป — เป็นการเสริม ไม่ใช่แทนที่
8

เมนูที่ 8: Feedback (ตารางประเมินผลคำตอบจากผู้ใช้)

เมื่อผู้ใช้ทั่วไปกดปุ่มถูกใจหรือกดไม่ถูกใจในหน้ากล่องแชท ข้อมูลเหล่านั้นจะถูกส่งเข้าตารางนี้ แอดมินสามารถเช็กได้ว่ามีบทสนทนาใดบ้างที่ผู้ใช้ประเมินว่า "ไม่พึงพอใจ 👎" เพื่อให้สามารถคัดลอกคำถามนั้นไปวิเคราะห์แก้ไขฐานข้อมูลความรู้ได้ตรงจุด

🔴 จุดเน้นวงกลมสีแดง: ไฮไลต์เมนู Feedback ในหน้าต่างแผงควบคุมหลัก สำหรับติดตามการให้คะแนนความพึงพอใจ
9

เมนูที่ 9: Unanswered (กล่องคำถามที่บอทไม่มีคำตอบ)

รวบรวมคำถามที่ RAG หาเนื้อหาอ้างอิงไม่ได้ และบอทแสดงข้อความ Fallback หน้าจอนี้มีความสำคัญในการเพิ่มพูนความรู้ของบอท โดยแอดมินสามารถคลิกปุ่ม **"Add to Knowledge"** บนคำถามที่พลาดไปเหล่านี้ และกรอกคำตอบที่ถูกต้องเพื่อสอนบอทให้ตอบได้สำหรับการถามครั้งถัดไป

🔴 จุดเน้นวงกลมสีแดง: แสดงตำแหน่งเมนู Unanswered (ทางระบบใช้ไอคอนเครื่องหมายคำถาม) และรายการคำถามจริงที่แชทบอทตอบไม่ได้ค้างไว้
10

เมนูที่ 10: Handoff (จัดการการขอส่งต่อคุยกับเจ้าหน้าที่)

เมื่อผู้ใช้กดยืนยันการขอติดต่อเจ้าหน้าที่จากแบบฟอร์ม Handoff รายการคำขอจะถูกบันทึกมาที่นี่พร้อมข้อมูลติดต่อกลับ แอดมินสามารถเข้ามาเช็กสถานะการติดต่อ จัดกลุ่มความเร่งด่วน และเมื่อดำเนินการแก้ปัญหาเรียบร้อยแล้วสามารถกดอัปเดตเป็นสถานะ "Resolved (ดำเนินการแล้ว)" ได้

🔴 จุดเน้นวงกลมสีแดง: แสดงตารางคำขอล่าสุดในเมนู Handoff พร้อมสถานะแสดงผล (Pending สีเหลือง / Resolved สีเขียว) และข้อมูลของช่องทางติดต่อกลับของผู้ติดต่อ
11

เมนูที่ 11: Integration (การเชื่อมต่อภายนอก)

แหล่งรวมโค้ดและข้อมูลทางเทคนิคสำหรับนำแชทบอทตัวนั้นๆ ไปใช้งาน เช่น โค้ดสำหรับคัดลอกไปวางฝังบนหน้าแรกของระบบอื่นๆ (Web Widget) หรือข้อมูล Webhook URL และ Token สำหรับนำไปเชื่อมต่อเข้ากับช่องทาง Facebook Messenger และ LINE OA ของหน่วยงาน

🔴 จุดเน้นวงกลมสีแดง: เน้นสัญลักษณ์ Integration และรายละเอียดกล่องข้อความบรรทัดคำสั่งโค้ด HTML script สำหรับคัดลอกไปฝังหน้าเว็บภายนอก
12

เมนูที่ 12: Bots Config (ตั้งค่าข้อมูลและธีมของบอทแต่ละตัว)

เมนูสำหรับการสร้างและบริหารความหลากหลายของบอท (Multi-Bot configuration) โดยแอดมินระดับสูงสามารถตั้งชื่อบอท, กำหนดพฤติกรรมการทักทายแรกเริ่ม (Welcome message), ร่างข้อความต้นฉบับสำหรับการทำงาน (System Prompt), เลือกโมเดล AI หลักและโมเดลสำรอง, รวมถึงเปลี่ยนภาพโลโก้และสีสันหลักของหน้ากากช่องพิมพ์แชท Widget

🔴 จุดเน้นวงกลมสีแดง: ไฮไลต์เมนู Bots ในกลุ่มการตั้งค่าเชิงระบบหลังบ้าน แสดงกล่องปรับแต่งพฤติกรรม ข้อความตัวตน System Prompt และหน้าตาการแสดงผลของบอทแต่ละเวอร์ชัน
13

เมนูที่ 13: AI Models (จัดการรายการและราคาโมเดลภาษา)

หน้าจอการเลือกใช้คลังโมเดลประมวลผลขนาดใหญ่จาก OpenRouter API (เช่น GPT, Claude, Llama) โดย Super Admin สามารถกดปุ่ม **"Sync Models"** เพื่อดึงโมเดลใหม่ๆ ที่อัปเดตบนคลาวด์ พร้อมทั้งเปิด/ปิดสถานะโมเดลที่จะให้บอทในสิทธิ์การดูแลเลือกนำมาประมวลผลได้อิสระ

🔴 จุดเน้นวงกลมสีแดง: แถบคำสั่งระบบไฮไลต์ที่ AI Models แสดงหน้าการเปิดใช้งานโมเดลภาษาของ OpenRouter และตารางราคาต่อ 1 ล้าน token
14

เมนูที่ 14: User Management (การจัดการสิทธิ์แอดมินหลังบ้าน)

มีไว้สำหรับ Super Admin เพื่อกำหนดหรืออัปเดตสิทธิ์ของเจ้าหน้าที่ในระบบ การสร้างบัญชีแอดมินระดับท้องถิ่น (Local Account), ปรับเปลี่ยนสิทธิ์และบทบาท (Super Admin, Admin, Viewer) และผูกสิทธิ์บอทแต่ละตัวเข้ากับบุคคล เพื่อป้องกันไม่ให้แก้ไขข้อมูลบอทของแผนกอื่น

🔴 จุดเน้นวงกลมสีแดง: ไฮไลต์เมนู User Management (ทางระบบใช้ไอคอนผู้คนจำนวนมาก) แสดงรายการเจ้าหน้าที่และปุ่มสำหรับสร้างหรือลบแอดมิน
15

เมนูที่ 15: Email Settings (การตั้งค่าการแจ้งเตือนอีเมล)

หน้าจอการกรอกข้อมูลการตั้งค่า SMTP Server เพื่อให้ระบบสามารถทำการส่งอีเมลแจ้งเตือนโดยอัตโนมัติ (เช่น ส่งเมลเข้ากล่องอินบ็อกซ์ของเจ้าหน้าที่เมื่อมีผู้ใช้กดส่งข้อมูลขอคุยกับเจ้าหน้าที่/Handoff เข้ามาในระบบ) เพื่อให้ตอบรับและแก้ไขสถานการณ์ได้ทันท่วงที

🔴 จุดเน้นวงกลมสีแดง: ไฮไลต์เมนู Email Settings แสดงฟอร์มการกำหนดค่าโฮสต์ SMTP, พอร์ตเชื่อมต่อ, อีเมลส่งหลัก และรหัสผ่านเชื่อมโยง
16

เมนูที่ 16: Global Settings (การตั้งค่าระบบความปลอดภัยและระบบจำกัดสิทธิ์)

หน้าสุดท้ายของการตั้งค่าระบบส่วนกลางทั้งหมด (System Settings) สำหรับกำหนดชื่อแอปพลิเคชันหลัก, ตัวเลือกการจำกัดการป้อนแชทต่อนาที/ต่อชั่วโมงต่อ 1 เซสชันแชท (Rate Limiting) เพื่อป้องกันการโจมตีจากบอทภายนอกหรือผู้ใช้ที่จงใจเรียกใช้โควตา และตั้งค่าขีดจำกัด Answer Cache

🔴 จุดเน้นวงกลมสีแดง: แถบทางซ้ายไฮไลต์เมนู Settings (ไอคอนฟันเฟือง) แสดงแบบฟอร์มการจำกัดความถี่การถาม และการตั้งค่าระบบแคชของคำถามพบบ่อยเพื่อประหยัดโควตาค่าใช้จ่าย AI
